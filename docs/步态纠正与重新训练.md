# 步态纠正与重新训练

## 重新训练原因与旧版本保留

用户指出原策略在平地也呈跳跃步态。此前只检查通过率、速度误差和跌倒，未检查接触节律，验收不完整。旧策略的通过结果仍作为历史实验保留，不能据此称步态正确。旧训练及自动发布进程已停止。

旧代码已逐文件复制至项目旁的`../mjlab_project_go2_complex_terrain_before_gait_retrain_20261105_145731/`，包括78个代码、文档、模型等文件以及未提交改动；SHA256与复制前工作区一致。该目录的`repository.bundle`保留Git历史，`BACKUP_INFO.md`说明恢复位置。原项目全部`outputs/`留在原处，未删除、未覆盖，后续使用新的时间目录。

原学生第200轮的4秒平地诊断：速度RMSE=0.02349m/s，700个有效平地采样中腾空占1.86%，两足支撑时非对角组合比例100%。这是短片诊断，不是新的完整回合验收；足以说明低速度误差不能证明步态正确。报告保留在`outputs/20261105_135550_370858_student_ppo_seed92000/evaluations/eval_20261105_150018_793051.json`。

## 新训练目标与实现

固定vx=0.3m/s，以对角腿交替支撑、平地无明显腾空的小步行走为目标；同时允许正常的三足、四足支撑过渡。当前任务没有鸿沟，不将持续腾空或前后腿成组跳跃作为平地行走方式。

从随机初始化的新教师开始，不加载原跳跃策略。仍为45维本体、10步历史、176维融合、12关节位置偏移及原PD控制；不增加相位输入。新参数集中在`env/config.py:GaitConfig`，接触统计和奖励位于`env/gait.py`，通过可选配置保留旧checkpoint加载能力。

- 用5N竖直接触力判断支撑；记录每只脚的腾空时长、重新触地、支撑组合及机身起伏。
- 惩罚四脚同时离地；在平坦区域额外惩罚单足支撑、前后/同侧两足组合、垂向速度和高度起伏。
- 平地两足支撑时奖励对角组合。以触地事件奖励适当摆动，惩罚极短摆动，避免碎步或原地站立冒充步态。
- 平坦区取平地、平台、过渡和终点内部，避开边缘0.35m；统计排除reset后0.5秒落地过程。上台阶不强制平地的双足支撑节律，但仍惩罚全身腾空。

这些奖励不能单独证明动作正确。评估和最终发布同时增加平地步态门槛：

| 指标 | 当前门槛 |
|---|---|
| 平地腾空采样占比 | ≤1% |
| 最长连续腾空 | ≤0.04s |
| 整条路线（含楼梯/碎石）的腾空 | 占比≤1%，最长≤0.04s，同样排除reset后0.5s |
| 平均支撑足数 | ≥1.9 |
| 两足支撑中的非对角组合占比 | ≤10% |
| 垂向速度RMS | ≤0.15m/s |
| 相对地面机身高度标准差 | ≤0.025m |
| 每只脚有效重新触地频率 | 0.35～3Hz，摆动至少0.08s |

同时保留完整路线成功率≥80%、vx RMSE≤0.1m/s，旧结果不豁免新步态要求。统计通过后仍须检查视频，确认不是拖脚、原地抖动或异常姿态；不只凭一个reward或接触率宣称步态正确。

后续选模先比较实际通过档数；未达标候选再用“最差通过率−0.1×归一化步态违规”衡量进展，兼顾路线完成和步态纠正，避免退回停滞模型。该系数由`--gait-selection-penalty`集中管理，只影响训练候选选择，硬验收不变。发布入口要求新步态配置启用且每个高度均满足步态门槛。
