# Go2 固定速度行走：环境与地形加载阶段方案

## 1. 本阶段目标

最终训练目标是在混合复杂地形上跟踪机体系速度指令 `[vx, vy, wz] = [0.3 m/s, 0, 0 rad/s]`，后期再开放速度范围采样和在线命令修改。本阶段先实现 Go2、混合地形和控制接口同场加载，并以独立测试文件验证 GPU 步进。

验收的是“场景与环境可用”，不是“策略已经学会行走”。零动作表示跟踪默认关节姿态；速度指令进入观测和奖励，不能直接把基座速度设为 0.3 来伪造策略行为。当前不启动 PPO 更新，也不加载 Go1 或旧 Go2 策略冒充已训练结果。

## 2. 文件职责与实际实现

| 文件/目录 | 职责 |
|---|---|
| `env/config.py` | 环境与控制参数、固定/范围速度指令配置 |
| `env/robot.py` | 加载项目内 Go2 模型，做必要的 mjlab 执行器适配 |
| `env/go2env.py` | 组装 SceneCfg、控制、观测、奖励和终止，提供 `create_env` |
| `env/observations.py` | 定义 48 维观测顺序 |
| `env/rewards.py` | 加载阶段的速度跟踪、姿态和平滑奖励 |
| `terrains/config.py` | 混合路线尺寸、三级难度、台阶与碎石参数 |
| `terrains/mixed_terrain.py` | 把全部区域构造成一个 mjlab 组合子地形 |
| `terrains/flat.py` | 地面与平台的静态长方体 |
| `terrains/stairs.py` | 上下楼梯与平台，保证下行后回到地面 |
| `terrains/rubble.py` | 固定 seed 的静态碎石碰撞块体 |
| `scripts/test_env.py` | 独立加载、射线/接触/步进检查、报告及预览图导出 |
| `models/unitree_go2/` | 本地 XML、素材、许可证和来源说明 |
| `domain_randomization/README.MD` | 后期随机化预留，本阶段关闭 |
| `run.sh` | 在本项目独立 uv 环境运行命令，默认使用 RTX 3070 |

遵循总方案的简洁风格：普通函数优先、4 空格缩进、模块开头说明用途，关键处解释坐标、维度、PD 和终止语义。不修改旧项目代码，不修改已安装的 mjlab 源码，不增加新的训练框架。

本阶段不建立空的 `rl/` 算法实现。后续从原自写 PPO 做必要的批量化适配，不能直接运行 mjlab 内置 PPO 作为替代。

## 3. 场景与机器人

模型从工作区原 `mujoco_project_go2_stairs/models/unitree_go2/` 复制到本项目，XML 和素材通过项目相对路径加载。来源与 XML 哈希记录在 `models/unitree_go2/SOURCE.md`。

每个独立环境有一个浮动基座 Go2 和同一套连续地形；多个环境共享已编译的静态地图几何，机器人状态彼此独立。单条路线内部包含全部区域，并非一个环境只分配平地、另一个环境只分配楼梯。

关节与动作顺序固定为 FL、FR、RL、RR，每条腿按 hip、thigh、calf 排列，总计 12 维。初始化为 hip=0、thigh=0.9、calf=-1.8 rad，基座初始高度 0.30 m。

原 XML 使用 torque motor。运行时移除旧 motor 和原 keyframe，再由 mjlab 创建原生 PD 位置执行器，避免重复驱动关节。磁盘 XML 保持不变。位置 PD 为 kp=40、kd=2；保留 XML 原有被动关节阻尼/摩擦，因此不能把该控制链说成与旧显式 PD 完全一致。

MuJoCo Warp 的 MULTICCD 与该模型原有非零 margin 组合不兼容，运行时将 geom margin 清零，实际碰撞体尺寸不变。物理接触选项以 `env/go2env.py` 中 SimulationCfg / MujocoCfg 为准，本阶段使用 elliptic cone 和 impratio=10；不是原 XML 的 impratio=100。

## 4. 同一环境内的混合地形

路线沿局部 +x 方向排列：

```text
平地 3.0 m
→ 上楼梯（4 级，每级踏面 0.35 m）
→ 平台 1.2 m
→ 下楼梯（4 级踏面，下降后回到地面）
→ 过渡平地 1.2 m
→ 碎石 3.0 m
→ 终点平地 2.5 m
```

总长 13.7 m，宽 3.0 m。路线起点位于局部 x=1.0 m、y=1.5 m，距离楼梯还有 2 m 供后续策略起步。按 0.3 m/s 估算，从该起点到路线末端约需 42 秒；回合上限暂设 90 秒，但本阶段没有实现终点通过/越界终止。

使用 mjlab `SubTerrainCfg` 和 `TerrainGeneratorCfg` 接口，一个 `mixed_course` 子地形包含整条路线。预生成三档难度，对应单级台阶高度 3、6、9 cm，四级总爬升分别为 12、24、36 cm。每段台阶内部等高；不同难度台阶高度不同。不是运行中突然修改脚下地形。

首版初始最高等级默认为 0，所有机器人从低难度路线起步。`--level 2` 表示初始可分配 0～2 级，不是把所有机器人强制设成第 2 级；课程自动升降尚未接入。

碎石是固定在地面上的 5×5 个简单不规则块体，低档高度 1 cm，高档上限 4 cm；布局由地形 seed 控制。当前没有可滚动石块，也没有质量/摩擦域随机化。全路线有基础地面，平台和台阶底部延伸到基础面以下，避免拼接裂缝。

## 5. 固定速度指令及后期预留

`VelocityCommandConfig` 集中管理：

```python
vx = (0.3, 0.3)
vy = (0.0, 0.0)
wz = (0.0, 0.0)
resample_seconds = 3.0
```

使用 mjlab 的速度命令生成项，上下界相等时，无论 reset 还是回合内重采样，命令都保持 `[0.3, 0, 0]`。不启用站立概率、heading 修正、初始化基座速度或随机外力。

后续范围训练只需在配置中调整上下界，不改动三维命令的位置和含义，例如 `vx=(0.1, 0.6)`。在线手动指令设置将在推理入口阶段增加；当前没有声称已完成键盘控制。`scripts/test_env.py` 专门检查当前固定 0.3 的任务，不是速度范围训练入口。

## 6. 观测、动作与 step/reset 约定

| 索引 | 内容 | 单位/坐标系 |
|---|---|---|
| 0:3 | 基座线速度 | m/s，机体系 |
| 3:6 | 基座角速度 | rad/s，机体系 |
| 6:9 | 重力方向 | 机体系 |
| 9:12 | 速度指令 vx/vy/wz | m/s、m/s、rad/s |
| 12:24 | 相对默认姿态的关节位置 | rad |
| 24:36 | 关节速度 | rad/s |
| 36:48 | 上一次执行的策略原始动作 | 未做网络缩放 |

本阶段共 48 维，未加入旧项目的步态相位与步频，也未加入地形高度扫描。不能直接加载旧的 58 维 checkpoint。后续训练接入时必须显式确认网络输入与观测缩放，不为兼容而静默补零。

动作是 12 维关节位置偏移，目标约为默认姿态 + 0.5×action rad，并按各关节硬限位截断。mjlab 动作项的 `clip` 截断的是缩放后的关节目标，不是原始 Gaussian 动作；后续 PPO 接入时需单独明确原始动作限幅及 log probability 约定。当前独立测试只使用全零动作。

物理频率 500 Hz，decimation=10，策略频率 50 Hz。`create_env(config, device)` 返回 mjlab 原生环境：

```text
reset() → (obs_dict, info)
step(action[N,12]) → (obs_dict, reward[N], terminated[N], truncated[N], info)
obs_dict["actor"] 的形状为 [N,48]
```

`auto_reset=False`。调用方先读取最终观测，再显式对 done 环境 reset，以保留后续 PPO 时间截断的 bootstrap 语义。当前终止项只有倾斜保护和时间截断；训练阶段还需补充基于实际支撑地形的跌倒高度、路线边界、完成条件等。

仅在 `--viewer` 交互展示阶段启用自动 reset，配合 mjlab viewer 的调用方式；这不改变默认训练对接接口。交互窗口本次未实际启动，离屏 PNG 已验证。

当前 reward 只有平面速度跟踪、倾斜惩罚与 action rate，按控制 dt 缩放。它用于验证环境接口，尚未完成复杂地形步态、能耗、足端接触/滑移等奖励设计。

## 7. 独立测试与输出

在项目根目录执行：

```bash
# 本地环境已建立；换电脑时根据锁文件安装
uv sync --frozen

# 单环境，200 个策略步 = 4 秒仿真，生成总览与近景图
./run.sh python -m scripts.test_env --num-envs 1 --steps 200 --render

# 小规模并行与不同初始难度检查
./run.sh python -m scripts.test_env --num-envs 16 --level 2 --steps 200

# 需要实际图形桌面时才开启；关闭窗口结束
./run.sh python -m scripts.test_env --steps 200 --viewer
```

测试流程：加载项目内模型 → 构建三档完整路线 → GPU reset → 检查 48/12 维接口及关节顺序 → 对最终碰撞模型逐级射线核对 → 零动作 PD 步进 → 验证固定命令/数值有效 → 用最终状态检查真实接触 → 保存报告，按需渲染预览。

这类射线检查验证台阶高度和区域碰撞几何，不证明机器人已穿越各区域。零动作 PD 检查也不证明策略能跟踪 0.3 m/s。

输出按 Asia/Hong_Kong 时间建立独立目录：

```text
outputs/<时间>_load_env_seed42/
├── config.json
├── terrain_manifest.json     # 最终编译地形几何、位置、尺寸与射线结果
├── randomization.json        # 当前关闭状态
├── report.json               # 步进结果、接触、实际速度与包版本
├── scene_overview.png        # --render 时产生
└── robot_closeup.png         # --render 时产生
```

渲染为测试后单独离屏执行，不影响无窗口步进流程。实际 GPU 设备、步数、耗时和实际 vx 写入 report；不能把目标 vx 当作测得的实际 vx。

## 8. 本阶段之后的训练工作

本阶段通过后，下一步才将原自写 PPO 迁入 `rl/`，适配 `[T,N,...]` 缓存和 GAE；补齐训练任务的奖励、地形相关终止/完成条件、观测缩放、动作概率及 checkpoint 定义，然后进行固定 0.3 m/s 训练。先用小规模检查 loss、接触与实际移动，再测 2046 个 Go2 混合地形环境的完整训练显存和吞吐。

训练后另写推理/评估/录像入口，输出完整路线视频与各区域表现。GitHub 仓库和最终 `.pt` 交付在有可用训练成果后进行；本阶段不发布空仓库或未训练权重。

## 10. 单条路线尺寸与 2048 个并行环境

单条路线、地图样本数与并行世界数分别管理：

| 概念 | 当前值 | 含义 |
|---|---|---|
| 单条路线尺寸 | 13.7 m × 3 m | 单台机器人一次连续穿越的空间 |
| 已生成路线样本 | 3 | 三档台阶高度及对应碎石布局 |
| 并行环境数 | 命令行设置，已实测 2048 | 独立机器人状态与物理世界的数量 |

多个环境可以分配到同一个地图样本的坐标，但属于不同物理世界，机器人之间不发生碰撞或共享状态。因此无需把单条路线扩大 2048 倍，也无需为每台机器人单独复制一套网格。即使原生 viewer 只显示少量机器人，也不代表后台只有少量环境。

按当前固定 0.3 m/s，起点到终点约 42 秒，单条路线可以作为首版速度跟踪和台阶接触任务。更大路线主要用于更长的连续任务；2048 并行本身不要求路线加长。

不过，三档地图只够加载阶段验证。正式训练拟将地形样本库逐步增加到“8 档难度 × 4 种布局 = 32 条完整混合路线”，这是下一阶段目标，当前未实现。每条路线仍含全部必需区域；布局变化包括碎石位置/尺寸、平台及过渡长度等，固定速度指令不变。先固定结构再逐项增加变化，避免同时扩大难度和改奖励导致问题无法定位。

实现多布局时，生成配置需要加入 `layout_id`，地形几何名使用难度和布局的联合标识，不能直接复制现有只按 difficulty 命名的生成器而造成名字冲突。保存布局 seed、参数、区域边界和各世界的分配信息。是否增加到更多布局、是否加长路线，依据分区域评估和完整 PPO 显存/耗时决定。地形库增大也会增加碰撞几何和构建成本，不能假定完全没有性能影响。

2026-10-31 实测命令：

```bash
./run.sh python -m scripts.test_env --num-envs 2048 --level 2 --steps 200
```

2048 个 Go2 环境各推进 200 个策略步，共 409600 个环境步，耗时 3.274 秒，合计约 12.51 万环境步/秒；未触发 reset，Warp 检测到 8192 个接触，初始地形等级分配为 0 级 712 个、1 级 661 个、2 级 675 个。原始报告在 `outputs/20261031_042144_725596_load_env_seed42/report.json`。

本次仍是起点平地上的零动作 PD 步进，三档路线的碰撞几何由射线检查核对；没有让 2048 台机器人完成混合路线穿越，也没有执行 actor 推理、rollout 缓存或 PPO 更新。该结果证明当前场景可以以 2048 个世界运行，不代表完整训练速度、显存或行走能力已验证。
