> 当前续训控制目录：`outputs/20261106_222653_454700_domain_randomization_pipeline/`。原213603批次已保留并标记为被停车课程修正替代；说明见文末。


2026-11-06。用户确认：外接D435i位于Go2头部上方，向下倾斜约20～50°。本次实际接入相机视角、真实周边几何、深度缺失及视觉分支适应，不只给旧深度图加像素噪声。

## 1. 相机安装与输入

| 项目 | 本次配置 | 依据与边界 |
| --- | --- | --- |
| 安装位置 | 暂用机身坐标(0.27,0,0.10)m，各轴±1cm | 用户尚未提供镜头相对机身根坐标的精确位置；是头部近似，不是实机标定结果 |
| 俯角 | 每个环境reset采样20～50°，标称35°；另加各轴±0.5°小安装误差 | 回合内固定，相机随后随机身运动，不逐帧跳变安装角 |
| 名义深度视场 | 水平87°、垂直58° | D435i名义参数；具体分辨率/模式必须读取真实内参 |
| 网络深度输入 | 64宽×48高、最近两帧，正常10Hz | 保留全幅图像后缩放；fx和fy独立计算，不能因为输出4:3就假设两者相同 |
| 深度定义 | 米制光轴Z-depth，固定裁剪0.15～3m并归一化[-0.5,0.5] | 保留网络原定义，0.15m是预处理阈值，不承诺真实设备近处均能测到 |
| IMU | 仍使用Go2机体IMU | 未将D435i自己的IMU未经坐标转换直接替代机体IMU |

官方产品规格列出D435i深度视场87°×58°：[Intel官方规格](https://www.intel.com/content/www/us/en/products/sku/190004/intel-realsense-depth-camera-d435i/specifications.html)。[官方D400系列数据手册](https://cdrdv2-public.intel.com/841984/Intel-RealSense-D400-Series-Datasheet.pdf)说明不同采集模式视场有区别。当前使用的是名义针孔模型，不包含相机完整畸变/双目匹配算法。

真实接入时读取实际depth stream的fx/fy/cx/cy和depth_scale，将深度单位转换成米；使用深度流自身的标定，不能混用RGB视场/内参。若保持全图缩放至64×48，分别缩放横纵内参；若裁剪、对齐RGB或改变相机模式，必须同步调整仿真相机。当前没有加入安装角度或帧有效标志到Actor，网络仍是176维融合与12关节输出。

20～50°是较宽的安装分布，不保证每个角度能看到同样远的地形。50°俯视时前方远处的楼梯可能不在画面中；训练不能凭空补回不可见信息，后续需分别验收20/35/50°而不只看平均分。

## 2. 墙壁和画面内容怎样随机化

新增`terrains/surroundings.py`，在每条原有混合路线侧边生成真实3D碰撞几何，参与MuJoCo/Warp射线与接触计算，不是把墙壁图片贴到深度图上。

| 结构 | 参数/采样 |
| --- | --- |
| 开放路线、左墙、右墙、双侧墙 | 每四种layout各一种结构；多个高度和几何seed进一步变化尺寸 |
| 通道净宽 | 复杂楼梯1.2～2.4m |
| 墙体 | 厚0.12m，顶高为最高累计台阶高度再加1.3～2m；起止位置变化 |
| 侧边物体 | 每侧一个box，长0.25～0.60m、宽0.15～0.25m、高0.25～1m，位置随seed变化 |
| 中央通行带 | 侧边物体内侧离路线中线至少0.55m，不生成横在正前方的封路墙 |

随机几何在创建场景时生成，不在行走中凭空跳动；每个物理世界通过地形等级/layout选择静态场景，reset更新所用布局/相机及物理参数。改变场景seed需新建下一批环境，不能把模型静态几何修改冒充每帧随机化。

这些结构表示直行楼梯两侧的环境变化，不包括L形/U形转弯楼梯、门框净高或自主绕过正面障碍。遇到封路墙时是否停车/绕行属于任务与导航设计，不应训练策略无视所有墙体。

策略输入仅深度，因此改变墙壁颜色本身不会改变输入；墙体位置、距离、高度、边缘和遮挡才会改变深度。反光、低纹理等材质问题先用深度缺失与噪声近似，不能宣称已复现D435i完整成像物理。

## 3. 避免错误的地面真值

- 可行走地面、楼梯、碎石在几何组0；周边墙体/物体在组4。
- 学生深度相机看到组0＋4；墙体有真实碰撞，不是只供渲染。
- `HeightQuery`只查询组0，避免把墙顶视为足下地面、抬高机身高度目标或污染地形扫描。
- RGB回放也显示组4，避免“策略看到墙但展示视频里墙消失”。

当前地形库包含相邻路线；真实射线可看到量程内的周边几何，不通过按世界删除碰撞体掩盖它们。图像预览为当前路线示意，深度图来自完整场景的真实射线。

## 4. 深度误差与时间处理

继承已有负载、摩擦、执行器、观测和动作延迟。新增/调整：

- 深度比例偏差每回合±1%。
- 距离相关噪声σ=(0.002＋0.002d²)m，继续作为待实测校准的近似。
- 随机无效像素1%；15%的采图事件出现一块12×10像素缺失，映射到far而不是伪造近障碍。标称环境不加这些扰动。
- 继续保留正常10Hz采图、少量丢帧和0/20ms图像传输延迟；收到的深度和采图时本体成对送入GRU。
- 20%环境保留当前相机标称35°和无扰动传感器；其余覆盖20～50°分布。该标称相机不是原195的25°旧相机。

完整默认开关仍关闭；旧checkpoint缺少新配置时保持25°、原视场和无周边物体，以免改变已发布195结果。

## 5. 为什么这次训练视觉网络

此前域随机化PPO冻结CNN/GRU，只有控制网络学习。仅在此基础上换成20～50°和墙壁，不能声称视觉分支已经适应。

新增`scripts/adapt_camera_scene.py`，用相同机器人状态的两套相机做顺序适应：

```text
真实部署近似：D435i视场＋20～50°＋侧墙/物体＋深度误差
    → 学生CNN/GRU → z_student
同一状态旧参考：原25°相机＋只看原地形组0
    → 冻结参考CNN/GRU → z_reference

损失 = 同一冻结控制网络的动作MSE ＋ 0.1×视觉latent MSE
```

共享本体、速度估计与动作网络全部冻结，只训练CNN/GRU。每个窗口10个视觉更新，前2个作为上下文，不计直接监督损失；跨窗口截断梯度。reset时立即编码新双帧并清对应隐藏状态，防止跨回合记忆串扰。控制动作由同状态旧视角参考策略生成，监督不调用尚不支持变速的新Teacher。

这是侧边场景/相机变化的一致性适应，不是完美地形真值监督，更不是避障学习。参考策略原本失败的楼梯能力不会因为模仿它自动修复。

适应期间暂时关闭图像传输延迟和丢帧以保证参考与学生采集时刻对齐；保留安装误差、深度误差及物理扰动。后续PPO与评估恢复图像丢帧/传输延迟。需用闭环验证判断视觉loss下降是否带来控制改善。
