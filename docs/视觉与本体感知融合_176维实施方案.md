# Go2 视觉与本体感知融合：176维技术设计与实施方案

> 状态：用户已批准实施并要求直接训练。当前176维网络、相机、PPO批量接口、蒸馏与评估入口已实现；正在分阶段训练，实际进展见《训练实施与运行记录》。已按要求删除 age / valid 网络输入。
>
> 日期：2026-10-31。本文将“本地感知”理解为机器人本体感知：IMU、关节编码器、上一时刻执行动作及其历史。仿真地形真值属于训练特权信息，不作为最终学生策略的额外传感器。

## 1. 修订内容、推荐方案与边界

本版取代之前的178维方案。删除的不是相机采样管理，而是送入动作网络的两维帧状态；固定10Hz采样、时间戳、reset清理和图像有效性检查继续由传感器模块负责。

| 项目 | 本版约定 |
|---|---|
| 最终融合 | 45 + 64 + 64 + 3 = **176维**，仅四路输入 |
| 动作MLP | **176 → 256 → 128 → 12** |
| age / valid | 不进入actor、GRU或critic，不以常数占位，也不藏进latent |
| 保留的内部信息 | 采图时间戳、采样计数、异常计数，仅用于调度、数据对齐和日志 |
| 未改变的结构 | 45维本体、10步历史、双帧深度CNN、视觉GRU128、3维速度估计 |
| 图示适用性 | 旧PNG和图解仍为178维历史版，不能作为本版实现依据 |

本版简化输入，是为了先建立固定采样、正常图像条件下的学习闭环；不把“多加特征”当作成功率保证。视觉对照实验和真实通过率仍按后文验收。

推荐采用“特权地形教师 → 深度视觉学生蒸馏 → 冻结视觉编码器的 PPO 微调”。最终学生只用深度图和本体观测，输出 12 维关节位置偏移，由现有 PD 执行器驱动 Go2。

主要设计选择如下，除已核对的依赖/API 外，均是本项目拟实施参数，不是已有实测结果：

| 项目 | 首版设计 |
|---|---|
| 任务 | 连续平地、上楼梯、下楼梯、碎石，固定机体系速度 `[0.3,0,0]` |
| 深度输入 | 高 48 × 宽 64，米制光轴深度，最近两帧 |
| 频率 | 物理 500 Hz；本体采样与 actor 50 Hz；深度采集及视觉编码 10 Hz |
| 本体输入 | 当前 45 维，最近 10 个策略时刻组成 `[10,45]` 历史 |
| 视觉分支 | 小型 CNN → 64 维 → GRUCell(109,128) → 64 维 |
| 本体分支 | 450 → 256 → 128 → 64；附带 3 维线速度估计 |
| 融合 | 当前本体45 + 历史特征64 + 视觉特征64 + 速度估计3，拼接为176维 |
| 动作头 | 176 → 256 → 128 → 12，Gaussian 均值及独立可训练 log std |
| 控制 | 默认关节姿态 + 0.5 × 限幅动作，关节限位后交给 PD |
| 算法 | 在已有自写 PPO 上局部适配；不换成 mjlab 内置 PPO |
| 并行 | 教师以 2048 为目标；视觉阶段先 256，分档验证至 2048 |
| 域随机化 | 保留目录，首轮关闭；不把噪声、延迟、外力当作首版训练前置条件 |

采用 GRU 有具体原因：前视相机看过的地面经过一段时间才到足下，单帧或两帧本身不足以保持这段记忆。GRU 只位于视觉分支、10 Hz 更新，避免把整个 50 Hz 控制器都改成循环 PPO。

这是参考论文后的工程化适配，不宣称逐项复现原论文；保留本项目的 Go2、mjlab、MuJoCo Warp 和自写 PPO。设计可实施的依据是现有批量物理环境、已核对的射线接口、标准 PyTorch 模块及分阶段训练；不承诺未经训练的收敛结果或未经测试的 2048 路视觉吞吐。

### 2.2 当前软件与硬件事实

本机 RTX 3070 8GB，现有独立环境为 mjlab 1.6.0、MuJoCo/MuJoCo Warp 3.11.0、Warp 1.14.0、PyTorch 2.11.0+cu128。已通过 2048 个 Go2 世界的零动作步进，但未包含视觉、训练网络、地形扫描或 PPO 更新。

已阅读本地 `camera_sensor.py`、`raycast_sensor.py`、`sensor_context.py` 和 `sim.py`：mjlab 支持针孔射线、GPU 相交查询及深度传感器，但默认 `env.step()` 每次都会调用 sensing。官方也提供相关传感器与批量射线 API。[mjlab 射线传感器](https://mujocolab.github.io/mjlab/v1.6.0/source/sensors/raycast_sensor.html)、[MJWarp 公共 API](https://mujoco.readthedocs.io/en/3.11.0/mjwarp/api.html)

因此不能只写“相机每 5 步读一次”，就声称底层传感器计算也减少到 10 Hz。频率控制必须放在实际射线调用之前，具体见第 5 节。

## 3. 从输入到 12 关节的完整链路

以下为本版有效的数据流。暂不引用旧178维PNG，避免图文混用；后续若重绘，应只保留四个最终融合输入。

```text
IMU角速度、重力方向、关节角/速度、上一执行动作、速度指令
             │ 50 Hz
             ├── 当前45维 p_t ───────────────────────────┐
             └── 10步历史 H_t → 本体MLP → z_p(64) ──────┤
                                      └→ v_est(3) ─────┤
                                                       │
前视深度图：48×64，10 Hz                               │
  → 米制校验/有效值处理/固定归一化                      │
  → 最近两帧 [2,48,64] → CNN → 64维                    │
  → 拼接采图时的 p_t(45) → GRU(128) → z_v(64) ────────┤
                                                       ↓
                                  拼接176维 → 动作MLP → μ(12)
                                                       ↓
                       训练：Gaussian采样；评估：直接使用μ
                                                       ↓
                         原始动作限幅[-1,1] → 默认姿态+0.5a
                                                       ↓
                                  按各关节限位截断 → PD目标
                                                       ↓
                              500 Hz PD执行与力矩限幅 → Go2
                                                       ↓
                                         新状态反馈到下一周期
```

视觉特征在两次新深度帧之间保持不变；当前本体、历史特征和速度估计仍每20 ms更新。相机时间戳只用于内部调度，不作为额外网络输入，因此相机10Hz不会把关节策略控制降为10Hz。

## 4. 本体输入、状态估计与观测权限

### 4.1 当前本体观测：45 维

| 索引 | 内容 | 数量 | 固定缩放 |
|---|---|---:|---|
| 0:3 | 机体系角速度 | 3 | ×0.25 |
| 3:6 | 机体系重力方向 | 3 | ×1 |
| 6:9 | 指令 vx、vy、wz | 3 | ×[2,2,0.25] |
| 9:21 | 关节角减默认姿态 | 12 | ×1 |
| 21:33 | 关节速度 | 12 | ×0.05 |
| 33:45 | 上次送入环境的限幅归一化动作 | 12 | ×1 |

关节顺序固定为 FL、FR、RL、RR，每腿 hip、thigh、calf。上一动作指原始动作裁到 `[-1,1]` 后、进入位置映射前的值；关节目标还有下一层硬限位，不把两种限幅混为一谈。

线速度真值不直接放入最终 actor。本项目现有 48 维观测中的前三维是模拟器机体线速度；新的感知模式应明确移除它，由本体历史估计，防止训练时偷偷依赖部署时不一定具备的信息。

投影重力由姿态估计获得；仿真可用真值姿态生成，实机需要 IMU/姿态估计器，并非直接把原始加速度当作重力。仿真四元数采用 `wxyz`；坐标变换集中实现一份。

缩放后统一做有限范围截断，例如 `[-5,5]`，不使用在线变化的均值方差。缩放与截断保存在模型配置/权重中，训练、回放、导出一致。深度采用独立规则，不沿用该截断。

### 4.2 本体历史和线速度估计

历史按从旧到新存放 `H_t=[p_(t-9),...,p_t]`，形状 `[N,10,45]`，展开为 450 维，覆盖约 0.2 秒。reset 时只清理对应环境，使用新回合首帧重复填充 10 次，不能混入上一回合动作。

历史编码：`450 → 256 → 128 → 64`，隐藏层 ELU，输出 Tanh 得到 `z_p`。速度估计头：`64 → 32 → 3`，隐藏层 ELU，末层线性，输出机体系 `v_est`，单位 m/s。进入融合层前 ×2 并截断；监督目标来自模拟器 `v_gt`，仅用于训练损失。

速度监督初始为 `L_vel = mean((2*v_est - 2*v_gt)^2)`，系数 0.1。它与 actor loss 合并在同一次优化中处理，不额外更新共享编码器后再假设 old policy 未变。

### 4.3 训练权限分离

| 信息 | 最终学生 actor | 教师 actor | 训练 critic / reward |
|---|---|---|---|
| 45维本体、历史、指令 | 是 | 是 | 是 |
| 深度与视觉记忆 | 是 | 否 | critic 不需要图像 |
| 估计线速度 | 是 | 是 | 可记录误差 |
| 模拟器真实线速度 | 否 | 只用于估计监督，不直接输入动作头 | 是 |
| 向下地形高度真值网格 | 否 | 是 | 是 |
| 真值足端接触/离地高度、路线进度 | 否 | 不直接输入动作头 | 是 |

学生推理入口不得读取教师高度扫描、真实基座线速度、地形 ID 或路线难度 ID。

## 5. 深度传感器、几何约定与采样

### 5.1 相机配置

| 参数 | 首版值 |
|---|---|
| 模态 | 单目深度，不输入 RGB，不做纹理/光照训练 |
| 分辨率 | H=48、W=64，单位米 |
| 安装位置 | 相对 `robot/base`：前方 0.27 m、横向 0、上方 0.10 m |
| 朝向 | 朝机器人 +x，向下俯视 25° |
| 视场角 | 垂直 60°，对应水平约 75.18° |
| 针孔内参 | fx=fy≈41.57 px，cx=31.5，cy=23.5 |
| 有效深度范围 | 0.15～3.0 m |
| 正常采样周期 | 5 个策略步，即 0.1 s |
| 两帧缓存 | 新、旧两帧固定按 `[D_(k-1),D_k]` 排列 |

64×48 是针对固定低速和 8GB 显存的首版选择，不是论文原始尺寸。审批后先在不同距离和台阶高度下看深度剖面；若 3 cm 台阶在任务所需距离不可辨识，先改为 H=72、W=96，并同步重新计算 CNN 展平维度、重新训练，不复用旧尺寸权重冒充兼容。不会先长时间训练再猜是否看清台阶。

### 5.2 相机坐标与光轴深度

机体系定义为 x 前、y 左、z 上。MuJoCo 相机沿局部 -z 看，局部 +x 向右、+y 向上；图像行号向下，因此射线的相机局部 y 要与行号反向。[MuJoCo 相机坐标说明](https://mujoco.readthedocs.io/en/3.11.0/XMLreference.html#body-camera)

设置俯角 θ=25°，相机坐标到机体坐标的旋转列向量为：

```text
R_BC = [[ 0, sinθ, -cosθ],
        [-1,    0,      0],
        [ 0, cosθ,  sinθ]]

pixel_ray_C = normalize([(u-cx)/fx, -(v-cy)/fy, -1])
```

安装四元数通过矩阵转换得到，不靠手猜符号。若复用某个现成针孔 pattern，先验证其行列方向与像素中心约定，不能直接 reshape 后假定正确。平面、台阶边缘、左右不对称障碍各检查一次，防止上下/左右翻转。

射线 API 返回沿归一化射线的距离 `r`，它不是光轴深度。按 `D_z=r*(-ray_C.z)` 转换，最终学生始终使用米制光轴深度。后续真实深度设备也要确认返回的是光轴深度或量程，不能混用。

### 5.3 GPU 深度实现路径

首版选择“针孔 GPU 射线生成深度”，不在每个环境创建 CPU `mujoco.Renderer`。项目内一个小型 `DepthSensor` 持有批量缓冲区和独立 BVH context，使用已核对的 MJWarp 公共 `create_render_context`、`refit_bvh`、`rays`，读取 `env.sim.wp_model/wp_data` 公共属性。调用形状为全部世界 × 全部像素；首版不依赖未确认的按环境子集渲染功能。

先只查询 group 0 的静态地形碰撞几何，关闭颜色、纹理和阴影。它提供具有遮挡关系的前视地形深度，不是直接读地形标签；但是没有机器人自遮挡或真实深度传感器伪影，不能作为已完成 Sim2Real 的证据。加入机器人自遮挡及传感器误差作为后期独立变更。

正常控制步不调用深度相交；仅在视觉 tick 执行 BVH 更新和批量射线，得到新图并提交缓存。教师的高度扫描也是项目内单独查询，不把深度相机注册进会每步强制 sensing 的默认管线。只有这个明确的性能需求才增加本地传感器适配，不复制整个 mjlab 环境类，不 monkey patch 第三方方法，不修改安装包。

可行性验证中保留 mjlab 原生针孔/相机路径作为小批量几何对照。如果项目内调度尚未通过，允许暂用原生 50 Hz 计算、10 Hz 提交图像来验证学习链路，但日志必须分别写两种频率；不能把它作为 10 Hz 计算优化或 2048 视觉能力验收。

### 5.4 预处理、reset 与内部采样管理

预处理固定为：无命中/非有限值替换为远端 3.0 m → 截断到 `[0.15,3.0]` → `(D-0.15)/2.85-0.5`，范围 `[-0.5,0.5]`。首轮不加深度噪声或随机裁剪。深度预处理后以 FP16 保存、送 CNN 前转 FP32；采样和训练使用同一量化后的数据。

不再构造 frame_age 或 frame_valid 特征。传感器内部保留 last_capture_time、采样步数和采集异常计数，用于确定何时执行下一次查询、对齐教师标签及保存日志；这些字段不能拼接进任何网络，也不为它们预留两列零值。

正常非视觉tick直接保持上次两帧缓存、视觉特征与hidden，不把相同图片再送一次GRU。正常视觉tick查询完成后才更新两帧并运行一次视觉编码。

每个像素无命中或超量程可按远端3m处理；整幅图全部是远端值也可能只是朝向无地形区域，不能仅按“有效像素比例小于5%”判定传感器故障。有效像素比例只记录诊断。需要区分场景内容、正常跌倒后的朝向变化与真正的查询失败。

真正的采集异常包括没有按调度返回结果、缓冲区shape/世界索引不正确或底层API报告错误。首版发生这类异常时保存诊断并停止本次运行，不在缺少故障输入及训练的情况下长时间静默沿用旧视觉特征。这样做是明确的运行检查，不是给策略增加故障标志，也不宣称已有安全降级能力。

reset 后必须生成新状态的深度，填成 `[D0,D0]`，并清零该环境 GRU 隐状态。不能把其他世界的新帧、上一回合深度或旧隐状态带入新回合。

当前公共批量射线没有本方案已确认的环境子集入口。若只有一部分环境 reset，首版允许全批重新查询，但只把 reset 环境结果提交其缓存，其他环境仍按正常 tick 更新。此类额外查询单独计数；高 reset 率可能使实际计算频率高于 10 Hz，必须在扩到 2048 时测量，不能隐藏这部分成本。

## 6. 网络结构与融合参数

### 6.1 深度 CNN

| 层 | 配置 | 输出形状（省略批量维） |
|---|---|---|
| 输入 | 两帧堆在 channel 维 | `[2,48,64]` |
| Conv1 + ELU | 2→16，kernel=5，stride=2，padding=2 | `[16,24,32]` |
| Conv2 + ELU | 16→32，kernel=3，stride=2，padding=1 | `[32,12,16]` |
| Conv3 + ELU | 32→32，kernel=3，stride=2，padding=1 | `[32,6,8]` |
| Flatten | 展平 | `1536` |
| Linear + ELU | 1536→128 | `128` |
| Linear + Tanh | 128→64 | `64` |

不使用预训练 ResNet、Transformer、BatchNorm 或 Dropout，避免增加依赖和 PPO 重算时的分布变化。分辨率若改为 72×96，展平维度变为 32×9×12=3456，其余设计保持可配置。

### 6.2 视觉时间记忆

每次新图时，将 CNN 的 64 维和采图时当前本体 45 维拼接成 109 维：

```text
x_k = concat(depth_cnn(D_(k-1),D_k), p_at_capture)     # [N,109]
h_k = GRUCell(input_size=109, hidden_size=128)(x_k,h_(k-1))
z_v = tanh(Linear(128,64)(h_k))
```

10 Hz 更新一次，两个视觉 tick 之间保持 `z_v` 和 `h`。隐藏状态由运行循环显式持有，shape `[N,128]`，按环境 reset；网络 forward 不在全局变量或模块内部偷偷维护单个共享 hidden。

两帧用于短时运动线索，GRU 用于保存更早看到的地形；本体 MLP 的 0.2 秒历史不能代替这段视觉记忆。GRU 输入原始固定缩放的本体，不接收后期 PPO 会更新的本体编码器输出，这是冻结视觉后仍能使用普通 PPO mini-batch 的条件之一。

### 6.3 拼接融合与动作头

| 输入块 | 维度 |
|---|---:|
| 当前本体 p_t | 45 |
| 本体历史 z_p | 64 |
| 视觉 z_v | 64 |
| 估计线速度（固定缩放） | 3 |
| 合计 | **176** |

融合顺序固定为当前本体、历史特征、视觉特征、缩放后的速度估计：

| 索引 | 输入 |
|---|---|
| 0:45 | p_t，45维 |
| 45:109 | z_p，64维 |
| 109:173 | z_v，64维 |
| 173:176 | scaled_v_est，3维 |

```text
fused = concat(p_t, z_p, z_v, scaled_v_est)  # [N,176]
```

这是沿最后一维连接，不是逐元素相加，也没有手工指定视觉和本体的占比。相机时间戳、有效性检查结果不能作为额外列，不能借用现有特征位置暗中加入。

融合采用直接拼接，随后 `176 → 256 → 128 → 12`。隐藏层 ELU，末层 Tanh 输出 Gaussian 均值 μ；每关节一个 `log_std`，初始 std=0.3，沿用原实现的合理范围约束。标准差不由 critic 或教师动作标签提供。

这版不增加 attention 或门控融合。先通过无视觉、乱序深度等消融确认视觉确实被使用，再决定是否需要更复杂结构。

### 6.4 教师与 critic

教师地形网格：x=-0.3～1.3 m，共 17 点；y=-0.5～0.5 m，共 11 点，总 187 点。网格随机器人 yaw 旋转、保持重力竖直方向向下查询。高度相对 `(base_z-0.27 m)` 表示，截断 ±0.5 m 并除以 0.5；未命中有独立统计并采用明确的边界值，不当成平地。

教师地形编码器为 `187 → 128 → 64`，隐藏ELU、输出Tanh。它替换学生的64维视觉特征，其余本体分支和动作头形状相同。教师也采用45+64+64+3=176维融合，不保留任何帧状态占位；这样教师与学生公共动作头可以按相同形状复制。

critic 与 actor 不共享可训练编码器。critic 输入为：本体 45 + 真实线速度 3 + 地形网格 187 + 足端接触 4 + 足端离地高度 4 + 归一化路线进度 1 = **244 维**；网络 `244 → 256 → 128 → 1`，输出标量 V。它只在训练中使用，不读取深度、不参与最终 12 关节推理。

按以上尺寸、含bias和12个log_std，学生actor约 **558283个参数（0.56M）**；教师actor约 **270875**，critic约 **95745**。删除两维只使动作头第一层减少2×256=512个权重，不改变CNN、GRU或critic。参数量是结构计算值，不是速度或显存实测。

## 7. 12 关节输出与控制接口

训练采样 `a_raw ~ Normal(μ,σ)`；播放和录像使用 μ。保留 `a_raw` 与对应 log probability 用于 PPO，另算 `a_exec=clip(a_raw,-1,1)` 给环境。

```text
q_target = clip(q_home + 0.5*a_exec, joint_lower, joint_upper)
tau_PD ≈ kp*(q_target-q) - kd*q_dot
```

动作头每 20 ms 更新一次；同一个 q_target 保持 10 个物理步。当前用 MuJoCo 原生位置 PD，而非 Python 每步手算上述力矩，因此公式解释控制含义，实际积分与力矩限幅由执行器完成。

| 关节 | 默认角度 | 当前位置范围（rad） | 执行器力矩上限 |
|---|---:|---|---:|
| hip | 0 | [-1.0472,1.0472] | 23.7 N·m |
| 前腿 thigh | 0.9 | [-1.5708,3.4907] | 23.7 N·m |
| 后腿 thigh | 0.9 | [-0.5236,4.5379] | 23.7 N·m |
| calf | -1.8 | [-2.7227,-0.83776] | 45.43 N·m |

kp=40、kd=2，保留 XML 被动阻尼/摩擦与当前运行时 margin 适配；不在本方案中同步调全部物理参数。这里的力矩数值是当前模型配置，不等同真机经过验证的安全额定值。

原始 Gaussian 动作、执行动作、最终关节目标分别记录含义；不能用执行动作的概率代替原始采样概率，也不能将关节目标再做一次默认姿态偏移。

## 8. 地形真值、奖励和终止

### 8.1 当前地形的精确高度查询

当前路线由静态、轴对齐长方体组成。教师高度网格、critic 足端离地高度和 reward 的地面基准，可由最终编译碰撞体计算：查询点落入哪些 box 的 xy 范围，就取这些 box 上表面的最大 z。它等价于当前地形的竖直向下射线命中，不必为教师额外渲染深度图。

`terrains/height_query.py` 从最终编译模型建立按路线分组的 GPU 表，使用当前环境对应路线的几十个 box，避免每个点遍历全部地图库。所有查询先正确转换世界坐标和路线原点；不能把共享地图坐标直接当作机器人局部坐标。

只对本阶段已支持的轴对齐静态 box 使用此方法，并与 CPU 碰撞射线在台阶、平台和碎石位置核对。若后期引入旋转石块、mesh 或高度场，必须扩展对应查询或改用真实射线，不能继续用不正确的简化表面。查询对象建立在场景编译后、第一次 reset/step 之前，初始化顺序在感知适配入口中显式处理。

### 8.2 reward 初始配置

以下是开始调试的候选权重，按原环境 `dt=0.02` 缩放，不是已收敛参数：

| 分项 | 未加权量 | 初始权重 |
|---|---|---:|
| 平面速度跟踪 | exp(-‖v_xy-c_xy‖²/0.1) | +1.5 |
| yaw 角速度跟踪 | exp(-(wz-c_wz)²/0.25) | +0.5 |
| 路线前进 | clip(世界系 vx,-0.5,0.5) | +0.2 |
| 倾斜 | gravity_body_x²+gravity_body_y² | -2.0 |
| roll/pitch 角速度 | wx²+wy² | -0.05 |
| 垂直速度 | vz² | -0.5 |
| 基座支撑高度误差 | 相对足下支撑高程的高度误差平方 | -2.0 |
| 控制努力 | 物理子步上的关节力矩平方和均值 | -0.00002 |
| 动作变化 | ‖a_exec-a_exec_prev‖² | -0.01 |
| 软关节限位 | 超出软限位部分平方和 | -1.0 |
| 足端滑移 | 接触足水平速度平方均值 | -0.2 |
| 非足端碰撞 | 有效的躯干/腿部触地指示 | -0.5 |

到达路线终点且经过全部区域，额外 +5；跌倒或越界额外 -1；这些是一次性事件项，不再乘 dt。首版不额外加大额生存奖励，不强行指定 walk/trot 接触时序，先防止站立刷分和奖励相互竞争。

足端法向接触力大于候选 1 N 时视为接触。支撑高程取接触足下地面高度的均值；全部足腾空时取四足下地面高度的中位数。目标基座离该支撑面高度初始取 0.27 m，不固定为世界 z=0。足滑使用接触条件，不能把摆腿速度当滑移。若暂时无法取得子步力矩统计，不用最后一帧冒充整个控制周期的控制努力，应标明该项尚未启用。

每项奖励分别记录，同时记录实际 vx、距离和接触；reward 上升但停在起点不算完成训练。视觉学生与教师使用同一任务奖励，蒸馏损失不是环境奖励。

### 8.3 终止、超时与区域记录

- 跌倒：倾斜超过 60°，或基座相对支撑地形高度持续低于候选 0.13 m，或有效躯干碰撞满足配置条件；阈值先在台阶边缘核对，避免把正常上台阶判为跌倒。
- 越界：相对路线中心横向超过候选 1.3 m，或离开本路线有效区域；使用机器人当前分配路线的原点。
- 成功：从规定起点连续通过所有区域，到达终点前的完成线；记录访问掩码，不能靠跨区域重置获得成功。
- 超时：90 秒，使用 `truncated=True`，不当作跌倒。
- 非有限仿真状态或接触缓冲溢出：报告运行错误并保存诊断，不静默算作正常回合或继续学习。

成功、跌倒、越界作为真正终止不 bootstrap；超时用 reset 前 critic 的最终输入 bootstrap。只有结束的环境清理历史、动作和视觉状态。

## 9. 分阶段训练流程

### 9.1 阶段 A：相机与感知数据闭环

先用 1～16 个环境，不更新网络。验证相机方向、米制深度、两帧顺序、10 Hz 调度、50 Hz 本体更新、reset 隔离、地形高度查询。输出 RGB 场景图、深度图、带数值范围的深度剖面和传感器调用计数。

深度相机只在批准后实现；当前的外部场景 PNG 不是机器人相机深度，不能直接用它证明阶段 A 已完成。

### 9.2 阶段 B：用自写 PPO 训练特权地形教师

教师不计算前视深度，用本体历史和 187 点地形网格学习固定速度行走，同时监督线速度估计。先检查小批量，再以 2048 个环境为目标。使用与学生完全相同的关节顺序、动作映射、控制参数和任务奖励。

训练先从平地和低难度完整混合路线开始；再加入 3～9 cm 等现有台阶和不同碎石布局。后续扩大至 8 档难度 × 4 布局，需要先实现布局 ID、唯一几何命名、清单和分配逻辑，不能只在配置里把数量写成 32。

教师达到第 13 节的基本闭环指标后再开始视觉蒸馏。教师不会走时，不用加深 CNN 来掩盖控制或奖励问题。

### 9.3 阶段 C：监督预训练与学生访问状态蒸馏

1. 冻结教师参数并设 eval/no_grad。学生本体编码器、速度估计头和动作头从教师复制；深度 CNN、GRU 和视觉投影随机初始化。
2. 初期由教师均值动作控制，冻结学生公共动作链，只训练视觉分支，学习教师的 64 维地形特征。
3. 再逐步放开学生控制比例，让学生访问自己的状态；在这些状态上重新查询冻结教师的均值动作。采用有限窗口的数据聚合，不只拟合教师的成功录像。
4. 可用混合执行动作 `(1-β)*μ_student+β*μ_teacher`，β 分批从 1 降到 0；β=0 的独立学生评估必须单独通过，不能把教师混合控制的成绩当作学生成绩。
5. 联合蒸馏时允许动作头、本体编码器和速度头以较低学习率更新，教师始终独立冻结。

初始损失：

```text
L_distill = 1.0*mean((μ_student-μ_teacher)^2)
          +0.1*mean((z_v-z_terrain_teacher)^2)
          +0.1*L_vel
```

动作监督每个 50 Hz 时刻使用当前状态教师标签；latent 监督只在新深度帧时计算，并与同一采图时间的教师特征对齐，不能拿旧图强行回归未来地形特征。实际可观测性不足时优先降低 latent 项，不靠增大系数强迫学生猜看不到的信息。

视觉分支是循环网络，监督训练必须按环境、回合、时间顺序取序列。首版采用 20 个视觉 tick（2 秒）的截断反向传播，序列中遇到 reset 立即清零 hidden；非回合起点增加最多 10 帧 burn-in，用当前参数重算前文 hidden，burn-in 不计损失。缺失前文时记录边界，不能把随机单帧 mini-batch 当作 GRU 训练。

只保存实际新采集的深度帧及 50 Hz 帧索引，不每个策略步重复存两张相同图片。运行时传感器 Tensor 可能会被下一次查询覆盖，采样缓存必须拷贝，不保留可变视图引用。

学生视觉学习率初始 1e-3，公共动作链 1e-4，Adam；序列 mini-batch 先取 16 个环境，gradient norm 上限 1。按验证集和独立闭环表现调节，不按固定梯度步数宣称收敛。

### 9.4 阶段 D：冻结视觉分支的学生 PPO 微调

学生已经能独立行走后，冻结 CNN、GRU、视觉投影及深度预处理；保留视觉 hidden 的正常在线更新。本体 MLP、速度估计头、动作头和 log_std 可用 PPO 更新，critic 单独训练。

此时将 `z_v` 作为环境提供的 64 维特征存入 rollout，网络不对 GRU 做 PPO 反向传播。因为视觉 GRU 的输入是固定缩放本体，不依赖被更新的本体编码器，所以这条冻结边界明确；不能一边更新 GRU 一边仍随机抽 latent mini-batch 冒充端到端 PPO。

首版不做循环视觉端到端 PPO。若后期确需解冻，必须新增顺序 mini-batch、hidden 初值、reset mask、burn-in 和新的显存验收，作为单独方案修订。

### 9.5 PPO 初始参数和关键数据约定

| 参数 | 教师 | 学生 PPO 微调 |
|---|---:|---:|
| 环境数 | 目标 2048，先小批验证 | 初始 256，后续分档扩大 |
| rollout 长度 T | 32 | 32 |
| mini-batch 样本数 | 1024 | 256 |
| epochs | 5 | 5 |
| actor lr | 3e-4 | 1e-4 |
| critic lr | 1e-3 | 3e-4 |
| gamma / lambda | 0.99 / 0.95 | 同教师 |
| clip epsilon | 0.2 | 0.2 |
| entropy 系数 | 0.001 | 0.001 |
| target KL | 0.015 | 0.015 |

沿用已有 PPO 的 clipped objective、GAE、actor/critic 优化器和 KL 早停语义。共享 actor 参数的速度监督一并受 actor 更新/KL 规则管理，不能在早停后继续用辅助 loss 改变 actor。

rollout 先保留 `[T,N,...]`，GAE 按时间反推、各世界独立截断；完成 GAE 后才展开为 `T*N`。采样时存 old log probability、value、mean/std；更新时固定 old 数据。超时最终观测、历史及 critic 特权输入都在 reset 之前取到。

阶段B的actor输入保存本体、历史和教师地形高度；阶段D保存本体、历史和冻结视觉latent。速度估计由actor的历史分支计算。两阶段都不保存或传入帧状态特征。冻结视觉后允许不保存 PPO 用不到的完整图像，但评估抽样仍保留深度供诊断。

## 10. 多频率控制与 reset 的执行顺序

每个世界维护历史、本次执行动作、两帧深度、采图时间、GRU hidden和路线进度。采图时间属于内部调度信息，不能因此进入网络。控制循环明确如下：

1. 首次 reset 后建立新本体历史，采集初始深度，清零 hidden，并用首帧执行一次视觉编码。
2. 在时刻t，使用p_t、H_t和最新z_v计算本体特征与速度估计，按176维四路拼接生成μ/std；训练采样a_raw，执行限幅后的a_exec。
3. 推进 10 个物理子步，得到时刻 t+1 的真实最终状态和 reward/done；更新该时刻本体历史。
4. 若到视觉tick，则在新状态上查询深度、更新两帧和GRU；否则保持视觉特征和hidden，仅维护内部采样计数。
5. 计算下一状态 critic 输入与 V，保存 transition。超时必须保留 reset 前结果，不使用新回合数据。
6. 仅对 done 世界 reset，清理其本体/动作/视觉历史；强制给这些世界获取新深度，之后才开始下一轮动作。

重算 terminal critic 不需要前视深度，因为 critic 使用特权状态。若终止恰好发生在视觉 tick，先用于本回合诊断，再用 reset 新帧替换该环境缓存，不能把两回合图像拼成一对。

normal tick 数量、额外 reset 查询数量、图像提交时间与实际底层调用次数分别记录。GPU Tensor 不逐环境转 NumPy；只在日志周期和视频导出时复制必要数据到 CPU。

## 11. RTX 3070 的显存与并行规模

### 11.1 能确定的张量预算

下表仅为张量尺寸计算，不包括物理状态、BVH、射线坐标/法线、优化器、反向激活、CUDA workspace 和显存碎片：

| 数据 | 256 环境 | 2048 环境 |
|---|---:|---:|
| 当前两帧深度，FP16 `[N,2,48,64]` | 3 MiB | 24 MiB |
| GRU hidden，FP32 `[N,128]` | 0.125 MiB | 1 MiB |
| 32 步本体历史，FP32 `[T,N,450]` | 14.06 MiB | 112.5 MiB |
| 冻结视觉 latent，FP32 `[T,N,64]` | 2 MiB | 16 MiB |
| 若盲目逐步存两帧原图，FP16 | 96 MiB | 768 MiB |

这说明采用冻结视觉 PPO 可以明显降低 rollout 图像缓存，但不能据此断言整套训练只占几十 MB。射线 world/ray 缓冲区和 BVH 也可能占用数百 MB，需要计入整卡显存观测，不能只看 `torch.cuda.max_memory_allocated()`。

正常 10 Hz、64×48 下，256 环境约每秒 786 万条像素射线，2048 环境约 6291 万条；若错误地每步执行，则后者约 3.15 亿条/秒，reset 还会额外增加查询。这里的“每秒”指仿真时间，不是本机已测得吞吐。

### 11.2 并行推进与可行性门槛

按 16 → 64 → 256 → 512 → 1024 → 2048 分档，先测传感器，再测推理/缓存，再测完整反向更新。每档记录初始化、物理、深度、CNN/GRU、actor、critic、优化耗时，物理接触溢出和整卡显存采样峰值。

视觉阶段默认 256 是明确的实施起点，不把现有 2048 零动作测试当作 2048 视觉训练证明。2048 仍是后续容量目标；如果 8GB 卡在实际负载下不能满足，报告容量和原因，先用已通过规模完成学习闭环，不能未经说明把目标改成较小规模后宣布全部完成。

建议稳定运行时整卡占用保持在约 7 GiB 以下，为突发接触和临时分配留空间，此为预算目标。先降低训练 mini-batch，再减少并行数；降低分辨率或改变模型必须记录配置和新 checkpoint 版本。不能只把更多环境塞进显存而不测实际采样效率。

### 12.2 兼容原则

现有 `create_env` 与 `scripts/test_env.py` 默认继续使用原加载模式，保留 48 维输入。感知模式通过独立适配入口和显式版本选择，不静默让老测试的观测从 48 维变 45 维。

拟定学生感知数据字段为 `proprio[N,45]`、`history[N,10,45]`、`depth[N,2,48,64]`，不定义vision_meta网络输入。训练专用字段与actor字段分开。PPO微调可用 `visual_latent[N,64]` 代替原图输入训练动作头，播放时仍需要视觉编码器。

拟定网络接口只接收必要张量：

```text
depth_encoder(depth_pair, proprio_at_capture, hidden_prev)
    -> visual_latent[N,64], hidden_next[N,128]

actor(proprio[N,45], history[N,10,45], visual_latent[N,64])
    -> mu[N,12], std[N,12]
```

actor内部计算历史64维和速度估计3维，再形成176维融合。接口不接收相机时间戳、age、valid或诊断字典。采集异常通过运行层处理，不通过补齐常数特征维持旧178维网络。

原 PPO 的变量名、buffer 字段、`take_action/store_transition/update` 语义优先保留。对 GPU 批量采样新增明确接口或参数，不无声改变旧方法返回类型；原 `.item()`、NumPy 缓存和重复推理位置做局部修改。已有 ActorNet/CriticNet 不因新网络而改名或整文件重写。

配置在所属模块集中，新模块在 `__init__` 一次传入所需配置；实际运行保存展开后的 JSON。深度预处理、关节顺序和动作映射各维护一份，不在训练、回放脚本中复制。

### 12.3 代码风格与依赖

- 优先普通函数和小型 `nn.Module`；传感器与 GPU 状态确需类时才使用类，不新增插件、工厂或多层基类。
- 4 空格缩进、清楚的变量和中间量，不写分号压缩语句，不为风格统一重命名已有变量。
- 每个文件有模块 docstring；注释解释光轴深度、时间对齐、GRU reset、GAE mask、动作概率等关键意图，不逐行翻译代码。
- 不新增 OpenCV、Transformer 库或另一个 RL 框架。现有 PyTorch、NumPy、MuJoCo、Warp 已覆盖首版计算；录像使用已安装的 imageio/ffmpeg 能力。
- 不修改 `.venv/site-packages`，不导入兄弟项目作为运行时依赖。实际复制的模型和 PPO 来源记录到 docs/CHANGELOG。
- 测试只覆盖会导致算法错误的关键点，不增加大量与任务无关的鲁棒性测试，也不静默吞异常或自动切换设备继续训练。

## 13. 阶段验收、评估与失败定位

下列性能阈值是审批后采用的初始目标，不是承诺所有地形均能一次训练达到。

| 阶段 | 进入下一阶段所需证据 |
|---|---|
| 感知 A | 平面/台阶深度正确，光轴转换及行列方向通过；目标10Hz正常调度、reset无串帧；静态高度查询与CPU射线一致 |
| 教师 B | 平地固定0.3能持续行走；低难度整条路线通过率目标≥80%；存活与速度误差不靠原地站立取得 |
| 蒸馏 C | β=0学生独立运行；低难度通过率达到教师至少80%，同时报告绝对通过率；不能只看latent MSE |
| 微调 D | 独立测试集上整条路线目标≥80%，移动段vx RMSE目标≤0.10 m/s；按3/6/9cm等难度分别报告 |
| 容量 | 真实相机查询、网络及更新同时开启，记录最大稳定并行数；若未通过2048则明确标注 |

每个难度至少采用 20 个预先固定、与训练不同的布局 seed，记录首次跌倒区域、上下楼梯/碎石到达率及条件通过率。初始只有三条路线时先报告小样本调试结果，不能把同一确定性地图重复20次称为20个独立布局。

至少比较三组：教师上限、仅本体学生、视觉+本体学生；再对视觉学生做置远深度/错序深度的诊断。若视觉失效后成绩不变，不能宣称已经实现有效视觉融合；若盲走本来就能通过当前地形，应增加未见布局和高度组合来评估感知贡献，而不是只展示成功片段。

典型排查顺序：

1. 教师不会走：先查指令/单位、奖励分项、PD、接触容量和终止，暂不改视觉网络。
2. 教师会走、学生不行：查深度朝向/范围、时间戳、训练与部署预处理、学生访问状态、GRU reset，再看latent可观测性。
3. 小规模正常、大规模异常：查world索引、batch缓存引用、接触/射线溢出、reset额外查询和显存峰值。
4. reward上升但动作怪：对照实测速度、足端滑移、非足端接触、动作饱和与视频，不只看总reward。

教师先按50次更新做工程短测，再分批训练和评估；长训练预算按500次更新一个检查批次管理。预算耗尽但未达标时记录失败与原因，不自动视为验收通过，也不无限无人值守续训。

## 14. 结果管理、权重与 PPT 展示

```text
outputs/<时间>_<teacher|distill|student_ppo>_seed42/

  metadata.json                      # 代码/依赖/设备、父checkpoint、观测与网络版本

  metrics.csv
  train.log
  checkpoints/{latest,best,final}.pt
  evaluations/
  videos/
```

checkpoint 包含 actor 全部模块、critic、优化器、训练阶段、配置、缩放、动作/关节顺序、随机状态和版本。采用显式 `observation_version=perceptive_176_v1` 和 `network_version=depth48x64_gru128_fusion176_v1`；旧58维/当前48维或旧178维结构权重不能直接当作该策略加载。分阶段初始化哪些模块、冻结哪些参数写入 metadata，不静默 partial load。

最终 `student_final.pt` 至少保存 CNN、GRU、视觉投影、本体编码器、速度估计头和动作头，以及相机/缩放/关节定义。推理代码持有 hidden 和历史并按10/50Hz调度；只保存12维动作MLP不足以恢复策略。首版以 PyTorch state_dict 与配套代码交付，C++ 导出格式在后续部署阶段另行验证，不同时新增两套推理运行库。

录制一段从起点连续通过全部区域的视频，再导出 PPT 重点片段。视频可并列 RGB 跟随镜头、最近深度、目标/实际 vx、台阶高度、当前区域和模型版本；正常速度播放，明确教师或学生身份、是否混合控制。

训练过程不创建交互 viewer。视觉传感器计算仍然必须执行，“无窗口”不意味着“无感知渲染成本”。录制视频的 RGB 外部镜头与策略深度输入分开，不让视频帧率改变策略频率。

最终代码及验证过的 `.pt` 按之前约定发布到新 GitHub 仓库/Release，保留模型与引用代码许可证。本轮不创建仓库、不上传权重。
