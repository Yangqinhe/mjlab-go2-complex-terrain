## 1. 目标与已有基线

在已有视觉＋本体感知Go2策略上增加负载适应、变速控制及Sim2Real所需扰动。目标是在同一策略中，根据速度指令在不同负载、接触条件和传感器误差下稳定行走；保留平地对角交替步态及复杂地形通过能力。

基线为已发布学生PPO195：固定vx=0.3m/s、vy=0，外部路线定位反馈产生wz；3/9/12/15/18/20cm六档，固定选择及独立复核共240/240完成。允许最长0.06s连续换足腾空，按50Hz接触统计。基线未启用域随机化，不代表已获得负载或变速能力。

SHA256：`1bb94242c4f80b7704daceaafee06ec594cbd0695fbe1563308ea8a36db22d10`。
基线结果与限制见[最终训练验收与交付](最终训练验收与交付.md)。原权重、所有outputs及已有代码备份保留；新实验独立保存。

明确区分三类变化：

- 域随机化：质量建模误差、摩擦、执行器响应、观测误差、延迟、相机差异等。
- 负载任务：机器人背上真实附加物体，改变总质量、质心、惯量，属于明确的任务条件。
- 速度任务：改变期望运动，而不是给实际机体速度随机加偏置；配置仍归`env/commands.py`及环境命令配置管理。

三者可联合采样，但不能通过一个总开关混在一起。地形种子、难度仍由`terrains/`管理。

## 2. 第一版能力边界

### 2.1 负载和速度目标

| 任务 | 第一版核心目标 | 后续扩展，不作为首版必须通过 |
| --- | --- | --- |
| 平地和3～9cm路线 | 负载0～1kg，vx=0.15～0.40m/s | 负载1～2kg、vx=0.10～0.50m/s |
| 12～20cm路线 | 负载0～0.5kg，vx=0.20～0.35m/s | 负载0.5～2kg及更宽速度范围，逐项评估 |

这些范围是设计目标，需要实验确认。不能默认“2kg＋20cm＋0.5m/s”可同时完成，也不把仿真2kg解释成该Go2版本的官方允许负载。真实电池、深度相机、支架和计算设备若已计入标称模型，则不重复计入附加负载；若未计入，应先建立对应的部署标称模型。

### 2.2 保持的网络接口

当前45维本体、10步历史、2×48×64深度及176维融合、12维关节输出保持不变：

```text
IMU/关节原始读数 → 固定偏差＋采样噪声 → 现有尺度与限幅
     → 当前p_t(45)＋H_t(10×45) → 本体64＋估计速度3
深度米制图 → 无效值/噪声/遮挡处理 → 采集时序与传输延迟

当前本体45＋本体64＋速度3＋视觉64 = 176 → 动作MLP → 12维动作
```

策略50Hz、物理与PD500Hz、正常深度采集10Hz；重置额外采图单列统计。动作缩放0.9为基线设置，首版不随机化该缩放。无帧年龄/有效标志输入，深度有效掩码只用于内部处理。Actor不增加真实负载、摩擦、真实线速度或地形ID；依靠历史适应，若适应不足再评估网络扩展，不预先改结构。

第一版critic保持244维，奖励与速度估计辅助监督可用仿真真值；不把这些真值接入Actor。

## 3. 负载的物理建模

### 3.1 为什么不能只增加机身mass

背部同样增加1kg，放在中央、前方或较高位置的俯仰/侧倾响应不同。负载需要同时改变总质量、组合质心和组合惯量；不能仅将机身质量乘一个系数，或把附加负载等价为向下外力。

首版负载为与机身刚性连接的固定箱体，不包含摆动、液体、绳索吊挂、回合内装卸。随机化只在reset执行，一回合保持固定。动态装卸需单独处理动量与任务切换，不在此版实现。

### 3.2 参数与采样

负载位置均为机身根坐标系：+X前、+Y左、+Z上，位置指负载质心。

| 项目 | 初始课程 | 联合课程上限 |
| --- | --- | --- |
| 附加质量 | 0～0.5kg | 核心0～1kg，扩展1～2kg |
| 前后位置 | x±0.03m | x±0.08m |
| 左右位置 | y±0.01m | y±0.03m |
| 上下位置 | z=0.10～0.14m | z=0.10～0.18m |
| 箱体全尺寸 | 0.20×0.12×0.08m | 首版固定；实机根据实际尺寸更新 |

拟定每批负载分布：30%无额外负载、50%核心范围均匀采样、20%当前已解锁上限附近。无负载时不对“负载位置”做物理解释，日志中标记为不适用。高阶负载只放在已解锁的地形/速度组合中，不靠不断降低所有任务难度掩盖失败。

箱体与机身碰撞几何需在可视化中核对；上述位置边界在实施时按真实机身/支架间隙收紧。无额外负载质量不为0的标称相机/支架，应独立计入标称模型。

### 3.3 组合惯量计算

用根坐标系表达标称机身质量m、质心c、质心处惯量I；负载质量m_p、质心r、负载质心处惯量I_p。刚性组合为：

```text
m_new = m + m_p
c_new = (m*c + m_p*r) / m_new
I_new = I + m*(||c-c_new||²E - (c-c_new)(c-c_new)^T)
      + R*I_p*R^T + m_p*(||r-c_new||²E - (r-c_new)(r-c_new)^T)
```

R为负载主轴到根坐标系的旋转，首版箱体与根坐标系对齐。箱体I_p由质量和全尺寸按标准长方体公式计算；再对I_new特征分解，写入MuJoCo主惯量与惯性坐标旋转，重算相关派生量。m_p=0时严格恢复基线。质量、惯量始终从不可变标称快照计算，禁止每次reset对上一次结果继续相乘/累加。

首版优先将刚性负载合并到base惯性中，避免每个环境增加关节、改变关节顺序及模型拓扑。这样能覆盖刚性负载动力学，但不覆盖负载外形的碰撞和视觉遮挡；若实际安装影响相机或机身碰撞，必须另加匹配的固定几何并重新验证，不能把质量等效模型称为完整背包模型。

### 3.4 与质量建模误差分离

先给标称本体施加小范围建模误差，再叠加显式负载。日志分别保存`body_mass_scale`、`payload_mass_kg`、`payload_com_body_m`和最终组合参数。不能把质量误差同时作用到负载两遍。机身质量统一缩放时惯量同步缩放；关节连杆首版保持不变，后续按测量扩展。

## 4. 速度指令随机化

### 4.1 指令模式及路线冲突处理

| 模式 | 指令来源 | 地形与用途 |
| --- | --- | --- |
| `fixed_route` | vx=0.3、vy=0，路线反馈生成wz | 基线回归，保持旧行为 |
| `variable_route` | 随机vx、vy=0，路线反馈生成wz | 第一版混合路线变速 |
| `free_velocity` | 随机vx/vy/wz，关闭路线纠偏 | 宽阔平地横移、转向、启停 |
| `scripted` | 明确时间表，选择上述路线或平地模式 | 独立复现和验收 |

当前`route_command()`会覆盖wz。首版不把随机wz直接叠加到路线纠偏；路线训练和自由速度训练使用独立模式。自由速度需匹配平地地块及对应越界/终止逻辑，不能在狭窄楼梯路线中随机横移后仍按直行终点评估。

复用已有三维command，新增配置字段提供默认值；保留原接口和字段名。命令采样放在`env/commands.py`，不放入`domain_randomization/`。

### 4.2 课程与时间调度

- 课程V1：vx在0.25～0.35m/s内，每回合采样并保持，vy=0。
- 课程V2：vx在0.15～0.40m/s内，每4～8s为每个环境独立采样新目标。
- 课程V3：平地加入零速、转向；扩展速度0.10～0.50m/s。高台阶仍先限制0.20～0.35m/s。
- 启停课程采用显式任务比例，初始仅平地；不要默认每次随机采样都可能在台阶边缘突然归零。

每次采样产生`command_target`，再由限加速度形成实际输入策略的`command_applied`：首版vx变化率上限0.20m/s²、vy 0.15m/s²、wz 0.50rad/s²，均为拟议值。默认不每20ms重新独立抽取目标，否则得到的是抖动指令。

Actor、critic、奖励、日志与评估在同一步使用同一份`command_applied`；同时记录目标指令，防止通过过度平滑隐藏响应迟缓。评估另报告目标到实际速度的响应时间、超调和停止漂移。

### 4.3 零速与奖励、终止的联动

当前奖励包含世界系+X进度，当前成功条件为路线终点。加入零速/横移/转向后必须调整：

- 路线正向移动保留进度辅助；零速时关闭正向进度奖励，不奖励“接到停止指令仍往前冲”。
- 自由速度模式关闭世界+X进度和路线终点奖励，使用机体系三维速度指令跟踪及姿态/平滑/接触约束。
- 平地零速段奖励低速度与稳定支撑，抑制抖腿；移动时才启用最小落足频率要求，不能逼站立机器人原地踏步。
- 接触步态的静止/移动分段由指令和预先规定的切换宽限决定，不能按实际速度低就跳过步态验收。站立段仍检查姿态、漂移及不腾空。
- 对负载不要提高力矩上限来换取通过；高度与动作幅度也不随负载随意补偿，先让策略在真实执行器约束内适应。

当前90s回合不能直接沿用到所有低速任务：路线行程约12.2m，0.1m/s理想情况下就需122s。首版正速度路线使用按指令行程预算确定的超时，建议先用200s上限；限制累计停留时长，并在生成脚本时确认理想行程预算可达终点。启停/自由速度采用固定时长任务，不以完整路线终点为必要条件。实际超时配置、预算及原因写入报告，不将超时算成功。

| 项目 | 初始范围 | 扩展范围 | 更新时机 |
| --- | --- | --- | --- |
| 足端接触滑动摩擦 | 0.8～1.2倍 | 0.6～1.4倍 | reset |
| 标称机身质量误差 | 0.95～1.05倍 | 0.90～1.10倍 | reset |
| 标称质心误差，不含负载 | 各轴±3mm | 各轴±5mm | reset |
| kp、kd | 分别0.95～1.05倍 | 分别0.90～1.10倍 | reset |
| 关节被动阻尼/摩擦 | 标称±10% | 标称±20% | reset |
| 有效输出上限 | 标称0.95～1.00倍 | 标称0.90～1.00倍 | reset |
| 电机额外响应/指令延迟 | 0～10ms | 0～20ms，后续依据实测 | 每回合定基值，允许小幅慢变 |
| 外力脉冲 | 先关闭 | 机身水平5～15N、0.10～0.20s，每8～15s一次 | interval |

摩擦优先通过足端对应接触属性实现，核对MuJoCo接触混合规则，记录实际有效接触摩擦；不要只改一个会被另一侧覆盖的数值。初期不同时随机化接触求解器、重力、恢复系数，避免把模型问题混入过多变量。

当前使用`BuiltinPositionActuatorCfg`。kp/kd应修改对应执行器gain/bias，不能只改关节被动阻尼冒充kd；输出上限调整使用原生effort限制，不在关节目标上乘“电机强度”。原生PD由引擎计算，若后期要模拟完整力矩响应滞后，需要单独评估执行器模型修改，不能声称目标延迟已覆盖全部电机动态。

外力为独立抗扰项，首次负载/变速训练不启用；站立和高台阶不同时叠加最大推力。扰动时间、方向、持续时间均记录，不用瞬间改机体速度冒充实测外力。

## 6. 观测噪声、偏差和动作时延

| 项目 | 初始 | 扩展 |
| --- | --- | --- |
| 陀螺角速度白噪声σ | 0.01rad/s | 0.02rad/s |
| 陀螺回合偏置 | 各轴±0.005rad/s | 各轴±0.01rad/s |
| 关节角白噪声σ | 0.003rad | 0.005rad |
| 关节速度白噪声σ | 0.05rad/s | 0.10rad/s |
| 关节编码器零位偏差 | ±0.005rad | ±0.01rad |
| 姿态小角度误差 | ±0.5° | ±1° |
| 状态通信延迟 | 先关闭 | 0～20ms，依据实测 |

白噪声采用零均值高斯并截到±3σ；偏置采用有界均匀采样并回合内保持。姿态误差通过小旋转作用于姿态后计算单位重力方向，不向重力三个分量独立叠加噪声造成非单位向量。

同一控制周期只构造一次带噪声本体观测缓存，历史、当前输入、采图时本体、日志复用它；当前`proprio()`可能被多处调用，不能每次调用都重新抽噪声。奖励/终止继续使用干净真值，速度估计监督目标与输入时间戳对齐。

动作延迟队列在500Hz子步消费，允许2ms分辨率；若首版只支持50Hz整步延迟，必须明确0/20/40ms离散档，不能把它标成任意毫秒延迟。先实现目标保持的真实调度再扩展参数。

`previous_action`统一表示进入PD链路的最近执行归一化目标，不是刚产生却尚未执行的目标。PPO的log_prob仍对应采样原始动作，不改成延迟后动作；下一步观测才能更新上一执行动作。关节编码器偏差先仅加到观测，不同时隐式改变物理零位；若实机PD也使用该偏差，应明确实现共同的测量/控制坐标转换，禁止重复施加。

每个环境reset只清该环境的动作/观测延迟队列和历史。标称站姿填充等待队列，避免清成不合适的绝对零关节目标。延迟参数及排队历史不泄露给Actor。

## 7. 视觉随机化与真实时序

### 7.1 拟议范围

| 项目 | 初始 | 扩展 |
| --- | --- | --- |
| 相机平移安装误差 | 各轴±3mm | 各轴±5mm |
| 相机旋转误差 | 各轴±0.5° | 各轴±1° |
| 焦距倍率 | 0.99～1.01 | 0.98～1.02 |
| 深度乘性偏差 | 0.995～1.005 | 0.99～1.01 |
| 随距离增长的噪声σ | 0.002＋0.002d² m | 按真实数据修正，d以米计 |
| 无效像素比例 | 0～1% | 0～3%，再加入小块缺失 |
| 帧丢失 | 初期关闭 | 0～2%，单独评估连续缺帧 |
| 采集后处理/传输延迟 | 0～20ms | 0～100ms，依据实际设备 |

噪声公式仅是待标定占位模型，不是特定相机规格；必须检查距离相关误差、边缘飞点、反光区域缺失的实测分布。深度噪声不能仅靠RGB颜色/光照随机化代替；当前网络不输入RGB，不做无效的纹理增强。

### 7.2 实现与时间对齐

当前`DepthSensor`通过自定义射线计算相机原点和朝向，并不是直接读取MJCF相机。安装误差必须进入每个环境的射线变换，焦距变化进入射线方向；仅调用`dr.cam_pos`不会自动改变当前传感器输出。

处理顺序：真实米制光轴深度→根据有效性处理无效值（含实际设备的0值）→有限深度噪声/偏差/缺失→近远截断0.15～3m→固定归一化[-0.5,0.5]。仅对有效深度加测量噪声；保留有效掩码，最终无效像素统一映射远端，避免给缺失值加噪声后变成伪障碍。训练与部署完全一致。

深度延迟队列每帧同时保存采集时刻深度、采集时带噪本体p_t和采集时间；按可用时刻交付GRU。不能将迟到深度与收到时刻的本体拼在一起。双帧按采集时间升序，丢帧时保持最近有效视觉latent，不凭空再执行一次GRU；不通过交换帧训练“鲁棒性”。时间戳用于内部调度和统计，不作为新网络特征。

真实部署应使用相同的采图时状态缓存/时间对齐机制。若实机无法对齐，需要把相应时间偏差作为独立训练条件，不能只在报告中声称已对齐。

自身遮挡先在完整传感器管线中验证机器人碰撞几何的射线可见性、安装点是否在几何内部及self-hit过滤，再接入训练；不能直接打开所有几何组假定结果正确。负载几何影响相机时一起建模；质量等效模型不具备该视觉效果。

## 8. 实现组织与最小修改范围

遵循[文件格式](文件格式.md)和[原方案](方案设计.md)：简洁、模块化、集中配置，保留已有PPO和数据接口，不引入新的第三方依赖。

```text
domain_randomization/
  README.MD           # 启用边界、采样时机及已实现状态
  config.py           # 动力学、负载、观测、动作、视觉范围；默认关闭
  dynamics.py         # 标称快照、负载惯性合成、摩擦与执行器事件
  observations.py     # 带噪本体缓存、偏置与观测延迟
  actions.py          # 每环境动作延迟队列及执行记录
  vision.py           # 相机误差、深度处理、帧传输队列
  disturbances.py     # 后期外力；实现时才创建

env/config.py         # 引用随机化配置，扩展命令模式与默认兼容项
env/commands.py       # 速度采样、限变化率、脚本与路线模式组合
env/go2env.py         # 模型随机化事件组装、per-world字段声明
env/training_task.py  # reset/step入口、观测缓存、任务奖励/终止分支
env/perception/       # 保留DepthSensor/VisualRuntime接口，调用视觉处理
scripts/              # 复用训练/评估入口，逐步增加配置参数和专项评估
```

仅按实现阶段创建实际需要的文件，不提前堆积空模块。负载与动力学函数归`dynamics.py`，速度归`env/commands.py`；不再建立第二套环境、PPO或通用插件框架。

参数以配置dataclass集中描述，构造已有task/runtime时传完整模块配置；操作以短函数为主，仅有持久队列/状态时使用小类。代码文件首行说明用途，关键注释解释组合惯量、时间对齐、reset隔离等易错点。

旧checkpoint没有新增字段时通过显式默认值兼容，所有随机化默认关闭；保留原键、变量名、关节顺序及网络shape。自由速度新增任务模式要单独标记配置版本，不能悄悄改变旧`fixed_route`奖励或终止语义。

## 9. mjlab/Warp接入与性能约束

已检查本机mjlab1.6.0安装源码存在`dr.body_mass`、`dr.pseudo_inertia`、`dr.pd_gains`、`dr.effort_limits`等入口。优先复用这些原生事件；显式负载组合是定制惯性操作，不能用随机函数名代替正确计算。

通过`EventTermCfg`和受支持的模型字段声明方式，在环境创建、CUDA图捕获前声明需要按世界展开的质量、质心、惯量、gain/bias、输出限制、摩擦字段。需要重算派生量的事件走框架重算路径；reset只更新对应`env_ids`。具体签名以本机锁定版本为准，不直接照搬网上main分支。

标称参数快照在模型标称化完成后、第一次随机化前保存。不同环境独立采样，回合内保持固定参数；模型拓扑、关节数、碰撞体数量不随reset变化，避免重建模型与CUDA图。几何尺寸/遮挡变化若需要动态拓扑，先改为固定几何集合或离线场景版本。

负载与物理采样用独立随机数流，速度、观测、视觉使用各自流；单独记录种子与采样值，避免新增噪声改变速度脚本。训练与独立评估使用分离seed。

已有2048环境容量结果只覆盖旧冻结配置。新增per-world字段、延迟队列和视觉反向传播后重新测256→512→1024→2048；每档真实rollout及PPO更新，报告整卡显存、Torch显存、吞吐、采图次数、数值异常和接触溢出。2048是待复测目标，不保证新配置仍能放入8GB。

## 10. 训练实施课程

| 阶段 | 新增内容 | 训练重点与进入下一阶段条件 |
| --- | --- | --- |
| D0 | 全部关闭，独立保存基线 | 恢复原行为、固定六档报告可复现 |
| D1 | 小负载＋窄vx范围，其他关闭 | 平地/低台阶先学负载与指令；保留基线回归 |
| D2 | 核心负载/变速＋小动力学随机化 | 逐档恢复到20cm；对应任务格达标 |
| D3 | 观测噪声、动作/状态延迟 | 不出现持续跳跃和明显振荡 |
| D4 | 视觉噪声、安装误差、延迟及遮挡 | 深度完整管线与真实时序一致 |
| D5 | 联合核心范围，平地启停/转向 | 用冻结评估集确认任务组合能力 |
| D6 | 1～2kg、更宽速度、外力 | 独立扩展实验，不拖延核心能力交付 |

每阶段建议20%原始无附加负载固定0.3任务、60%当前已解锁核心组合、20%当前课程边界；早期未解锁边界份额回分到核心组合。环境间独立采样；高负载/高速/高台阶不是三个独立均匀分布的无限制笛卡尔积。配置明确列出允许组合，报告各格样本数，不只展示总成功率。

不同时提高负载上限、速度上限和地形难度。每次先扩大一项，验证通过再联合作用。进阶依据路线成功率、分速度跟踪误差及步态，不只看训练reward；失败回退当前课程并保留检查点和失败报告。

从195初始化学生PPO，先解冻本体历史编码器与速度估计头，使用保守学习率并监测KL；视觉编码器在D1～D3可先冻结。D4需要学习视觉误差时再逐步解冻CNN/GRU，接入顺序训练/BPTT并限制梯度。现有在线视觉runtime使用`no_grad`且部分训练配置冻结视觉，仅改`requires_grad`不能保证视觉得到梯度；实施时复用既有顺序蒸馏训练路径或明确接通PPO视觉训练，再验证实际参数变化。

现有固定速度Teacher不能直接作为整个变速负载任务的监督上限；如PPO适应不足，先训练覆盖同任务分布的Teacher，再顺序蒸馏、PPO微调，不能让学生长期模仿不支持新指令的Teacher。保留KL早停与数值异常检测，按真实新任务预算记录训练总步数。

## 11. 评估矩阵与验收标准

先冻结评估协议再训练；训练选择集与最后独立集分开。最终新任务独立评估seed预留50000～50009，实施前检查未被使用并记录锁定；不能反复用最终独立集调参。

### 11.1 核心矩阵

- 平地/3cm/9cm：负载0、0.5、1kg × vx=0.15、0.30、0.40m/s。
- 12/15/18/20cm：负载0、0.5kg × vx=0.20、0.30、0.35m/s。
- 负载0.5kg及以上至少覆盖中置、前置、后置三种位置；左右偏载在专项集验证。每个位置单独计算指标，不能合并掩盖薄弱位置。
- 每个核心高度/负载/速度/位置格，选择集至少5seed×4布局=20完整首回合；最终独立集10seed×4布局=40完整首回合。纯平地四布局为四种初始条件，并明确没有碎石布局的含义。
- 变速脚本单独测试：0.15→0.30→0.40→0.20；另做平地0→0.30→0、vy与wz测试，记录每段持续时间及允许场地。
- 原195的固定0.3、无额外负载六档回归单独保留，不拿旧任务通过替代新任务通过。

核心矩阵很大，先用小规模筛查，最终候选再完整执行；正式报告不得只保留筛查通过的格。扩展区域单独列“成功/失败/未测”，不计为核心通过。

### 11.2 干扰测试分层

每个核心矩阵先测标称物理与传感器；独立联合扰动集覆盖预先定义的小/中/边界参数组合，每个随机组合保存完整配置。另做单因素摩擦、延迟、深度缺失、相机偏差扫描，定位瓶颈。分层报告样本数和成功率区间，不将重复回合当独立新案例。

首版建议每个核心格完整路线完成率≥80%、稳态vx RMSE≤0.10m/s、无数值异常；新变速任务还报告vy/wz RMSE及以下指标。基线无扰动六档回归要求每档≥95%，速度/步态继续通过；未达到则不能替换195作为默认发布模型。

变速评价同时给出：

- 全时段相对`command_applied`的RMSE，不删除切换失败；相对`command_target`的响应延迟、超调。
- 稳态RMSE：每次限加速度过渡完成后再等待预先固定0.5s，统计其后片段；必须同时发布全时段指标。
- 平地停止后1s起的速度范数均值≤0.03m/s、随后3s相对停止位置漂移≤0.10m，站立无腾空、姿态稳定。
- 50Hz接触统计最长腾空≤0.06s；移动段保留腾空比例、错误足配对、垂直速度、落足频率等检查；零速段单独定义站立检查。
- 平地移动落足频率原0.35～3Hz先作为回归参考；新低速/高速适用阈值需在评估协议中预先确定并记录版本，不根据某份候选的失败临时放宽。
- 各速度/负载的力矩饱和比例、关节限位比例、能耗、姿态峰值和失败位置；通过率高但持续打满电机的策略不作为实机候选。

平地稳态指标不能代表楼梯瞬态。启停、转向、负载偏置均需实际测试，不从恒速路线外推。最终评估关掉探索噪声，但保持该测试规定的物理/观测扰动；“关掉探索”不等于“关闭域随机化”。

## 12. 文件管理、日志与发布

每次训练保存到新的`outputs/<时间>_<阶段>_seed<编号>/`，不得覆盖195目录或其他历史输出。配置中明确训练任务、允许负载/速度/地形组合、每阶段比例、随机化范围和版本。

除原有checkpoint/config/deployment/terrain等文件外，规划新增：

```text
randomization.json        # 开关、分布、单位、课程范围、独立seed
payload_manifest.json     # 标称模型质量/惯量、负载尺寸和组合算法版本
command_manifest.json     # 模式、目标范围、限变化率、超时与脚本
randomization_samples.jsonl # 每次reset物理参数与命令切换事件，不逐像素记日志
evaluation_matrix.csv     # 每个任务格的样本数、完成率、误差及步态
failure_cases.json        # seed、负载位置、速度、扰动、失败地形/原因
```

逐步噪声用种子、配置与固定的采样调度复现；可复现关键失败另外保存传感器/执行目标时序。不能只保存seed却不保存阶段、参数范围和代码版本。日志采用批量缓存写入，避免每步同步GPU和写盘影响吞吐。

视频按任务标注真实负载、指令及实际速度、台阶高度、扰动条件；保留接触曲线，正常播放速度导出PPT片段。完整评估后才更新默认权重及GitHub Release；新Release与原195并存。

## 13. 验证范围与实施完成定义

只做容易出错且影响物理/时序的必要检查，不堆积与实现重复的测试：

1. 全关闭恢复旧行为；新增默认配置可加载旧checkpoint。
2. 零负载严格恢复标称；组合质量/质心/惯量解析核对，参数有限且物理有效，无reset累积漂移。
3. 两个环境采不同负载/摩擦时互不串扰；部分reset不清其他环境缓存。
4. 指令目标、限变化率、奖励和日志时间一致；零速无进度奖励冲突；低速路线时间预算正确。
5. 一次控制步仅一份噪声缓存；动作延迟索引、上一执行动作、采图时本体及迟到帧顺序正确。
6. 相机安装变化确实改变射线，0深度/缺失处理一致；开启反向训练后所选编码器参数实际更新。
7. 以真实训练复测显存/吞吐，随后执行冻结的矩阵与独立复核，而不是以零动作吞吐代替。

阶段实现后在CHANGELOG记录改动及实际效果，失败结果也记录；未经实测的指标始终标为目标。实机前还需完成SDK关节映射、时序/推理预算、姿态与通信超时保护及实际传感器标定；完成域随机化不自动等于允许实机20cm测试。
