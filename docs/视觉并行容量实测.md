# 视觉并行容量实测

本记录对应176维视觉学生的容量验证，不代替行走成功率和步态验收。教师2048环境训练、零动作2048步进、4环境相机校准都不能证明2048视觉PPO容量。

## 测量入口

`scripts.benchmark_visual_capacity`按16、64、256、512、1024、2048分档调用真实学生PPO训练：深度48×64双帧、10Hz正常采图、CNN/GRU推理、50Hz控制、rollout缓存和actor/critic反向更新同时开启。视觉编码器冻结，符合当前PPO方案，不声称2048环境端到端视觉反向训练。

默认每档20次更新、horizon128，每世界51.2秒仿真，覆盖完整路线长度的负载；记录实际训练配置、数值异常、采图/reset计数、吞吐和优化耗时。初始minibatch为环境数×64，对应每个rollout 2批×5epoch；显存不足时先依次减半minibatch、相应增加批数，并保存每个失败日志。

整卡显存由独立nvidia-smi进程每100ms采样，包含Warp和CUDA等分配。PyTorch峰值从环境构建开始记录，仅覆盖Torch分配，不能代替整卡峰值。NVML监测从训练进程启动持续到退出；CUDA组件微基准另启进程，避免其缓存影响下一档整卡测量。benchmark生成的训练权重仅用于容量测试，传入权重的SHA256在结束时核对保持一致。

组件微基准单独记录初始化、物理/PD策略步、观测构造、深度查询、CNN/GRU、actor、critic；它们在路线起点短预热后测量。复杂地形接触、重置和完整PPO的实际负载以长采样日志为准，不能把起点微基准当作复杂地形行走速度。PPO更新耗时由真实训练CSV记录，返回指标的.item()已经同步该更新。
